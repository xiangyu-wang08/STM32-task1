# 通信科协 STM32 软件任务一 · 三位 LED 二进制计数器

我用 STM32F103C8 和三只 LED 显示 0～7，用两个按键实现单步递增和自动递增。这个任务让我第一次碰到一个问题：按键事件只在一次扫描中出现，运行模式却要一直记住。

## 任务书要求与实现

| 要求 | 我的实现 |
| --- | --- |
| 三只 LED 显示 0～7 的八个二进制状态 | PA0、PA1、PA2 分别驱动低位、中间位和高位。LED 低电平点亮，上电三灯全灭，显示 `000`。 |
| 按一次递增键加 1，超过 7 回到 0 | PB1 是递增键。松手后确认一次操作，按 `000 → 001 → 010 → … → 111 → 000` 的顺序更新。 |
| 用切换键在手动和自动模式间切换 | PB11 是切换键，第一次操作启动自动计数，再操作一次停止，保留当前显示。 |
| 自动模式约每 500 ms 递增一次，超过 7 回到 0 | 每次更新后执行 50 次 10 ms 延时，等待时持续扫描停止键。实际间隔还包含扫描和函数执行时间。 |

任务书还要求给 LED 串联限流电阻、处理按键消抖，并准备任务报告和演示视频。这里记录程序的实现、调试和复现步骤。

## 从点灯到计数

我先在 [LED 驱动](Hardware/LED.c) 里把三个 GPIO 配成推挽输出，分别验证低电平点亮和高电平熄灭。写计数时，我想用二进制位的变化规律代替逐个枚举亮灯组合。最低位每次计数都翻转，中间位每两次翻转一次，最高位每四次翻转一次。主程序用 `num` 记录 0～7，用 `subnum` 和 `thirdnum` 分别记录后两位的翻转间隔。手动和自动分支沿用这一规律。

接下来我在 [按键模块](Hardware/Key.c) 把 PB1、PB11 配成上拉输入。检测到低电平后延时 20 ms，等待松手，再延时 20 ms 后返回按键事件。`Key_GetNum()` 返回 `0` 表示没有事件，`1` 表示手动递增，`2` 表示开启自动递增，`3` 表示关闭自动递增。

## 调试过程

### 自动递增开启后关不掉

最初写切换逻辑时，我发现自动计数开始后，再按切换键不能正确关闭。排查到 `Key_GetNum()` 里的局部变量每次进入函数都会重新初始化，程序忘记了上一回已经开启过自动递增。

我在按键函数中加了 `static uint8_t temp = 0`，让它在两次调用之间保留上一次切换结果。第一次按切换键返回 `2`，下一次看到 `temp == 2` 就返回 `3`。本次有没有按键仍然由每次初始化为 `0` 的 `KeyNum` 表示。主程序里的 `maintain` 只在收到 `2` 或 `3` 时更新，因此扫描返回 `0` 时仍能继续保持当前模式。

### 有了关闭指令，为什么还是有时按了没反应

修正状态保存后，我发现如果在自动计数的延时中按下又松开，程序有时仍然漏掉操作。原先只在主循环开头读按键，处理完一段自动计数才回来扫描，按键可能已经恢复为高电平。

我把约 500 ms 的等待拆成 50 次 `Delay_ms(10)`，每次短延时之前执行一次 `Key_GetNum()`。收到停止事件后，先记录停止状态并退出等待循环，再退出外层的自动递增循环。报告里记录了我用这套轮询方式测试后能够正常切换。这里的 10 ms 是两次空闲扫描间的延时设置，按住不放时还会等松手。

## 如何复现

1. 在 Keil µVision 打开 [project.uvprojx](project.uvprojx)，编译并下载到 STM32F103C8。
2. PA0～PA2 接三只低电平点亮的 LED，每路串联限流电阻。PB1、PB11 各接按下时拉低的按键。
3. 上电确认 `000`。点按 PB1 八次，观察从 `001` 递增到 `111`，第八次回到 `000`。
4. 点按 PB11 进入自动模式，观察约每 500 ms 更新一次。再次点按 PB11，确认停在当前计数，再用 PB1 继续单步递增。

计数和模式切换入口在 [User/main.c](User/main.c)，软件延时在 [System/Delay.c](System/Delay.c)。
